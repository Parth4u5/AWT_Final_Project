# ADR-005: Own the session model; use `arctic` only for OAuth

- **Status:** Accepted
- **Date:** 2026-11-19
- **Source:** `docs/BUILD_LIST.md` §4.1 (contested point 4), §20 (D11, D12, D14, D24), §2.2

## Context

The legacy auth is the most security-sensitive part of the codebase: a committed `JWT_SECRET` and
`MONGO_URI`, an insecure `"dev_secret_change_me"` fallback, a backdoor that auto-creates an admin,
privilege granted by email address, and a token in `localStorage`. The brief requires the rebuilt auth to
be defensible under interview scrutiny, not merely convenient.

## Decision

**Own the session model** and use the spec-compliant `arctic` library only for the OAuth 2.0 client
(Google/GitHub) (§4.1 point 4, D24). Specifically:

- Short-lived access token plus rotating refresh token with **token-family reuse detection** and family
  revocation — "the most interview-relevant code in the repo".
- Access token in memory, refresh token in an httpOnly cookie; CSRF double-submit and
  `SameSite=None; Secure` + `credentials: include` so the code tolerates any deployment topology (D12).
- `@node-rs/argon2` for password hashing — prebuilt N-API, so "a node-gyp failure would be a serverless
  deploy failure" (D11).
- A shared rate-limit store, not in-process memory — "in-process limits are bypassable on serverless"
  (D14). No admin-by-email or auto-created admin.

## Consequences

- **Positive:** the auth flow is explainable line by line, and the most valuable interview code is ours.
  Rotation plus reuse detection is a real, testable security property; the leaked-secret incident is
  resolved by rotating `JWT_SECRET` in place and treating all old tokens as compromised.
- **Negative:** about three days versus roughly one with a turnkey library (§4.1), and we must maintain
  the session/schema code ourselves. A shared store (Redis) is required from Phase 4 onward.

## Alternatives considered

- **`better-auth`.** "Faster but opaque" — we would lose exactly the code we want to be able to defend
  (§1.7, §4.1). Rejected.
- **Hand-roll OAuth 2.0.** "OAuth is the _boring_ 60%, so we use a spec-compliant library rather than
  hand-rolling it" (§4.1). `arctic` covers that part.
- **`argon2` native addon.** Requires node-gyp at deploy time; `@node-rs/argon2` avoids a serverless
  failure mode (D11).
- **In-process rate limiting.** Bypassable on serverless; rejected in favour of a shared store (D14).
