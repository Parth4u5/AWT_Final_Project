# ADR-001: Adopt TypeScript everywhere

- **Status:** Accepted
- **Date:** 2026-11-19
- **Source:** `docs/BUILD_LIST.md` §0, §3, §6 and decisions log D3, D23 (§20)

## Context

The existing project is all JavaScript — even pure logic modules carry a `.jsx` extension
(`engine/parser.jsx`, `api/Client.jsx`) — with no type checking and no tests. The API contract is
duplicated by hand across the client and server, so "the hardest problem in a TS migration of a 2-app
project is **type drift between client and server**". The build list sets the goal directly: "Turn the
current AWT final project into a production-quality, TypeScript web app with a real execution engine",
and "makes it modern — TypeScript everywhere". This project is going on a portfolio and is read by
people assessing the author for a job, so it must be defensible under "walk me through a decision".

## Decision

Migrate the whole codebase to TypeScript in Phase 1, with no behaviour change in that phase:

- `packages/shared` defines one Zod schema per request/response and the error envelope; both apps import
  those schemas, and types flow from `z.infer<typeof schema>` (D3 — "one source of truth, no build-order
  coupling").
- `apps/api` is migrated first (smaller surface) with `strict` and `tsc --noEmit`; `apps/web` follows with
  `.jsx` renamed to `.ts`/`.tsx`, `allowJs: false`, and no `any` enforced by ESLint.
- `packages/engine` is pure TypeScript with no DOM and no Node-only APIs, so the same code runs in a Web
  Worker and on the server; its instructions, scopes, events and errors are discriminated unions.
- Quality is enforced by CI: `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm build` on every PR.

## Consequences

- **Positive:** a change to a shared schema breaks compilation in both apps — "drift becomes a compile
  error, not a production incident". The typed event stream becomes the contract for replay, storage,
  share links and JSON export (D9). It is interview-defensible and removes an entire class of runtime
  validation bugs.
- **Negative:** roughly one week of migration work (Phase 1), and the "no-op refactor" gate means that
  week deliberately ships no new features. Strictness is applied in steps — `exactOptionalPropertyTypes`
  lands on `packages/*` and `apps/api` first, and only later on `apps/web`, where it fights Mongoose
  `.lean()` results and Zod `.optional()` inference.

## Alternatives considered

- **Stay in JavaScript.** Faster today, but leaves the client/server contract untyped and makes the
  engine's tagged event stream impossible to enforce — exactly the drift the monorepo is meant to kill.
- **JSDoc type annotations.** No build step, but weaker inference and no way to generate a single shared
  contract; not defensible as a deliberate quality choice.
- **Flow.** An extra, less ecosystem-compatible type system; the whole toolchain (React, Zod, Fastify,
  Vitest) is TypeScript-native.
